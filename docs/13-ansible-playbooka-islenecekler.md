## 1. Decoder checksum doğrulaması — `af-packet` bölümü

**Sorun:** `eth0` üzerinde donanım checksum offload açık
(`rx-checksumming: on`, `tx-checksumming: on`). Ağ kartı checksum'ı kendisi
hesapladığı için Suricata paketleri "bozuk" sanıyor ve SID **2200075**
(`SURICATA UDPv4 invalid checksum`) alarmı üretiyordu.

**Ölçüm:** 12 saatte **37.994** yanlış pozitif. Düzeltme sonrası 2 saat 50 dakikada **0**.

```yaml
# af-packet -> interface: eth0
# ESKI:
    checksum-checks: kernel
# YENI:
    checksum-checks: no
```

> Not: Alarmı üreten kural `decoder-events.rules` içindedir. Bu nedenle
> `stream.checksum-validation` ayarını değiştirmek **yetmez** — decoder katmanı
> ayrı bir yoldur. İlk denemede bu atlandığı için sorun çözülmüş sanılmıştı.

## 2. Stream checksum doğrulaması — `stream` bölümü

Aynı offload gerekçesiyle TCP stream motoru için de kapatıldı.

```yaml
# stream:
# ESKI:
  checksum-validation: yes
# YENI:
  checksum-validation: no
```

## 3. Alarm kayıt ayrıntısı — `eve-log` / `alert`

**Sorun:** Her alarm kaydına ham paket, 4 KB payload, payload'ın okunabilir kopyası,
HTTP gövdesi ve etiketli paketler yazılıyordu → **kayıt başına ~4.6 KB**.
`/var/log` log2ram ile tmpfs (RAM) olduğu için bu doğrudan RAM tüketiyordu:
2 saat 50 dakikada 20.4 MB (≈172 MB/gün) yalnızca `eve.json` için.

**Ek gerekçe:** `payload-printable: yes` gerçek trafik içeriğini düz metin olarak
loglara yazar — gizlilik açısından da istenmeyen bir durum.

```yaml
# outputs -> eve-log -> types -> alert:
# ESKI:
        - alert:
            payload: yes
            payload-buffer-size: 4kb
            payload-printable: yes
            packet: yes
            metadata: yes
            http-body: yes
            http-body-printable: yes
            tagged-packets: yes
# YENI:
        - alert:
            payload: no
            payload-buffer-size: 4kb
            payload-printable: no
            packet: no
            metadata: yes          # baglam korunur
            http-body: no
            http-body-printable: no
            tagged-packets: no
```

Alarmın kendisi (hangi kural, kim, kime, ne zaman) ve `metadata` bağlamı korunur;
yalnızca hacimli adli döküm kapatılır. Derin inceleme gerektiğinde bu ayarlar
geçici olarak geri açılabilir.

## 4. Log dizini izinleri

```bash
# ESKI: drwxrwxrwx (777) root:root  — herkes yazabilir
# YENI:
chmod 750 /var/log/suricata
chown root:adm /var/log/suricata
```

Bu değişiklik Ansible tarafından yönetiliyor olabilir; playbook'ta dizin izni
tanımı varsa oraya da işlenmelidir.

**Ölçülen sonuç** (değişiklik sonrası 10 dakikalık pencere):

| `eve.json` günlük | ~172 MB | **27 MB** |

## 4b. Not — `eve-optimized.json` ve promtail (dokunulmadı)

`suricata-smart-logger.service`, `eve.json`'u okuyup tekrarlayan alarmların ağır
payload'larını ayıklayarak `eve-optimized.json` yazar. Payload'lar Suricata
tarafında kapatıldığı için ayıklayacak bir şey kalmadı; dosya artık `eve.json`'un
neredeyse birebir kopyası (hatta Python'un JSON biçimlendirmesi yüzünden bir tık
daha büyük) — yaklaşık **30 MB/gün fazladan RAM yazımı**.

**Ama kaldırılmamalıdır:** `promtail` bu dosyayı okuyup Loki'ye gönderiyor
(`/etc/promtail/config.yml`, `job_name: suricata`,
`__path__: /var/log/suricata/eve-optimized.json`). Devre dışı bırakmak
Grafana'daki Suricata panellerini bozar.

**İleride sadeleştirmek istenirse:** promtail doğrudan `eve.json`'u okuyacak şekilde
ayarlanır ve `suricata-smart-logger` kaldırılır. Bu bir boru hattı değişikliğidir,
Grafana panelleri doğrulanarak yapılmalıdır.

## 5. Öneri — gürültülü kuralların bastırılması (henüz uygulanmadı)

Checksum gürültüsü giderildikten sonra kalan alarmlar da büyük ölçüde düşük değerli
protokol anomalileri. 2 saat 50 dakikalık ölçümde:

| Adet | Kural |
|---|---|
| 2358 | `SURICATA STREAM reassembly overlap with different data` |
| 924 | `SURICATA TLS invalid record type` |
| 498 | `SURICATA HTTP Unexpected Request body` |
| 102 | `SURICATA STREAM Packet with invalid timestamp` |
| 66 | `SURICATA STREAM excessive retransmissions` |

> GRO/LRO/TSO/GSO offload ayarlarının tamamı `eth0`'da zaten **kapalı** olduğu için
> bu alarmların kaynağı offload değildir; gerçek protokol anomalileridir
> (yeniden iletimler, asimetrik trafik, TLS oturum artıkları).

Bunları bastırmak **tespit kapsamını daraltır** — bu bir güvenlik kararıdır ve
bilinçli alınmalıdır. Uygulanacaksa iki adım gerekir:

```yaml
# 1) suricata.yaml su an threshold dosyasini OKUMUYOR; direktif eklenmeli:
threshold-file: /etc/suricata/threshold.config
```

```
# 2) /etc/suricata/threshold.config icine:
suppress gen_id 1, sig_id 2210044     # STREAM Packet with invalid timestamp
suppress gen_id 1, sig_id 2210045     # STREAM reassembly overlap (SID dogrulanmali)
```

> SID'ler bastırmadan önce `fast.log` üzerinden doğrulanmalıdır.

## Doğrulama komutları

Playbook çalıştırıldıktan sonra değişikliklerin korunduğunu kontrol etmek için:

```bash
grep -n "checksum-checks:"      /etc/suricata/suricata.yaml   # -> no
grep -n "checksum-validation:"  /etc/suricata/suricata.yaml   # -> no
sed -n "60,69p"                 /etc/suricata/suricata.yaml   # payload/packet -> no
ls -ld /var/log/suricata                                      # -> drwxr-x--- root adm
suricata -T -c /etc/suricata/suricata.yaml                    # yapilandirma gecerli mi
```

Gürültü ölçümü (yeniden başlatmadan sonra biriken):

```bash
grep -c "invalid checksum" /var/log/suricata/fast.log   # -> 0 olmali
du -sh /var/log/suricata
```
